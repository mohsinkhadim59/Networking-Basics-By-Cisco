## IPv6 Addressing and Hexadecimal 
Before understanding IPv6, it’s important to know about the **hexadecimal number system**. Unlike the normal decimal system (0–9), hexadecimal uses **16 symbols**:  
0–9 and A–F. These extra letters allow computers to represent very large numbers in a shorter and more readable way.

IPv6 addresses are written using hexadecimal because IPv6 addresses are **very large**. An IPv6 address is **128 bits long**, which is much bigger than an IPv4 address. Since every hexadecimal digit represents **4 bits**, an IPv6 address ends up with **32 hexadecimal digits in total**.

These 32 digits are grouped into **8 sections**, and each section is called a **hextet**.  
Each hextet contains **4 hexadecimal digits (16 bits)** and is separated by a **colon**.

>[!Example] Example of an IPv6 Address in Full Form
2001:0DB8:0000:0000:0000:00FF:0042:8329


This format is called the **preferred format** because it shows all 32 hexadecimal digits clearly.

## How IPv6 Addresses Are Shortened (Compression Rules)

Because the full format can look long and confusing, IPv6 allows two simple rules to make addresses easier to read.

### Rule 1: Remove Leading Zeros
You are allowed to remove **only the zeros at the beginning of a hextet**.

```bash
`Example`
0DB8 → DB8  
0042 → 42

```
But you **cannot remove trailing zeros**, because that would change the value.

---

### Rule 2: Replace Continuous Zero Sections with "::"
If there are **one or more full hextets made entirely of zeros**, they can be replaced with a **double colon (::)**.  
This can be done **only once in an address**.


```bash
`Original`
2001:0DB8:0000:0000:0000:00FF:0042:8329

```

**After applying both rules:**
```bash
2001:DB8::FF:42:8329
```

This makes IPv6 addresses **shorter, cleaner, and easier to work with**.

If there are multiple zero sections of the same length, the **first one is usually compressed**.

# IPv6 Address Compression Rules

IPv6 addresses are written in hexadecimal and are 128 bits long. Because these addresses can become very long and difficult to read, IPv6 defines **two compression rules** to simplify how addresses are written without changing their meaning.

---

## Rule 1: Omit Leading Zeros

This rule allows you to **remove only the leading zeros** from each hextet (16-bit block).  
Trailing zeros **cannot** be removed because that would make the address ambiguous.

### Key Idea

• Only zeros at the **start** of a hextet can be removed  
• Zeros at the **end** must stay  
• Every hextet must still exist (no skipping yet)

### Examples of Rule 1

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | 2001:0db8:0000:1111:0000:0000:0000:0200 |
| No Leading 0s | 2001:db8:0:1111:0:0:0:200               |

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | 2001:0db8:0000:00a3:ab00:0ab0:000b:1234 |
| No Leading 0s | 2001:db8:0:a3:ab00:ab0:b:1234           |

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | 2001:0db8:aaaa:0001:0000:0000:0000:0000 |
| No Leading 0s | 2001:db8:aaaa:1:0:0:0:0                 |

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | fe80:0000:0000:0123:4557:89ab:cdef:0001 |
| No Leading 0s | fe80:0:0:123:4557:89ab:cdef:1           |

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | 0000:0000:0000:0000:0000:0000:0000:0001 |
| No Leading 0s | 0:0:0:0:0:0:0:1                         |

| Type          | Format                                  |
| ------------- | --------------------------------------- |
| Preferred     | 0000:0000:0000:0000:0000:0000:0000:0000 |
| No Leading 0s | 0:0:0:0:0:0:0:0                         |

---

## Rule 2: Double Colon  (: :)

This rule allows you to **replace one continuous group of all-zero hextets** with a **double colon (::)**.

### Important Rules

• You can use `::` **only once** in an IPv6 address  
• It must replace **only full zero hextets**  
• If more than one zero group exists, use `::` on the **longest group**  
• If both groups are the same length, compress the **first one**

---

### Examples of Rule 2 (After Applying Rule 1 First)

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | 2001:0db8:0000:1111:0000:0000:0000:0200 |
| Compressed | 2001:db8:0:1111::200                    |

---

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | 2001:0db8:0000:ab00:0000:0000:0000:0000 |
| Compressed | 2001:db8:0:ab00::                       |

---

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | 2001:0db8:aaaa:0001:0000:0000:0000:0000 |
| Compressed | 2001:db8:aaaa:1::                       |

---

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | fe80:0000:0000:0123:4557:89ab:cdef:0001 |
| Compressed | fe80::123:4557:89ab:cdef:1              |

---

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | 0000:0000:0000:0000:0000:0000:0000:0001 |
| Compressed | ::1                                     |

---

| Type       | Format                                  |
| ---------- | --------------------------------------- |
| Preferred  | 0000:0000:0000:0000:0000:0000:0000:0000 |
| Compressed | ::                                      |

---

 >[!Notes] 
• `::` can **never appear twice** in the same address  
• `::` only replaces **full zero blocks**, not partial ones  
• `::1` represents the **loopback address**

>[!tip] **IPv4 Issues**
>- The depletion of IPv4 address space has been the motivating factor for moving to IPv6. IPv6 has a larger 128-bit address space, providing 340 undecillion possible addresses. When the IETF began its development of a successor to IPv4, it used this opportunity to fix the limitations of IPv4 and include enhancements.
>- Example is ICMPv6, which includes address resolution and address autoconfiguration not found in ICMPv4.
>- Both IPv4 and IPv6 coexist and the transition to only IPv6 will take several years. The IETF has created various protocols and tools to help network administrators migrate their networks to IPv6. The migration techniques can be divided into three categories: Dual Stack, Tunneling, and Translation. Dual stack devices run both IPv4 and IPv6 protocol stacks simultaneously. Tunneling is a method of transporting an IPv6 packet over an IPv4 network. The IPv6 packet is encapsulated inside an IPv4 packet, similar to other types of data. NAT64 allows IPv6-enabled devices to communicate with IPv4-enabled devices using a translation technique similar to NAT for IPv4. An IPv6 packet is translated to an IPv4 packet and an IPv4 packet is translated to an IPv6 packet.

>[!tip] **IPv6 Addressing**
>- IPv6 addresses are 128 bits in length and written as a string of hexadecimal values. Every four bits is represented by a single hexadecimal digit; for a total of 32 hexadecimal values. 
>- IPv6 addresses are not case-sensitive and can be written in either lowercase or uppercase. In IPv6, a hextet that refers to a segment of 16 bits, or four hexadecimal values. Each “x” is a single hextet, which is 16 bits or four hexadecimal digits. Preferred format means that you write IPv6 address using all 32 hexadecimal digits. 

>[!example] 
>- fe80:0000:0000:0000:0123:4567:89ab:cdef.
There are two rules that help to reduce the number of digits needed to represent an IPv6 address.
>
>- **Rule 1 –** Omit Leading Zeros. You can only omit leading zeros, not trailing zeros.- 01ab can be represented as 1ab
>- 09f0 can be represented as 9f0
>- 0a00 can be represented as a00
>- 00ab can be represented as ab
>
>- **Rule 2** – Double Colon. A double colon (: :) can replace any single, contiguous string of one or more 16-bit hextets consisting of all zeros. For example, 2001:db8:cafe:1:0:0:0:1 (leading 0s omitted) could be represented as `2001:db8:cafe:1::1`. The double colon (: :) is used in place of the three all-0 hextets (0:0:0). The double colon (: :) can only be used once within an address, otherwise there would be more than one possible resulting address. If an address has more than one contiguous string of all-0 hextets, best practice is to use the double colon (: :) on the longest string. If the strings are equal, the first string should use the double colon (: :).
