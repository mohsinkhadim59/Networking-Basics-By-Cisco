## IPv6 Addressing and Hexadecimal 
Before understanding IPv6, it’s important to know about the **hexadecimal number system**. Unlike the normal decimal system (0–9), hexadecimal uses **16 symbols**:  
0–9 and A–F. These extra letters allow computers to represent very large numbers in a shorter and more readable way.

IPv6 addresses are written using hexadecimal because IPv6 addresses are **very large**. An IPv6 address is **128 bits long**, which is much bigger than an IPv4 address. Since every hexadecimal digit represents **4 bits**, an IPv6 address ends up with **32 hexadecimal digits in total**.

These 32 digits are grouped into **8 sections**, and each section is called a **hextet**.  
Each hextet contains **4 hexadecimal digits (16 bits)** and is separated by a **colon**.

>[!Example] Example of an IPv6 Address in Full Form
2001:0DB8:0000:0000:0000:00FF:0042:8329


This format is called the **preferred format** because it shows all 32 hexadecimal digits clearly.

## How IPv6 Addresses Are Shortened (Compression Rules)

Because the full format can look long and confusing, IPv6 allows two simple rules to make addresses easier to read.

### Rule 1: Remove Leading Zeros
You are allowed to remove **only the zeros at the beginning of a hextet**.

```bash
`Example`
0DB8 → DB8  
0042 → 42

```
But you **cannot remove trailing zeros**, because that would change the value.

---

### Rule 2: Replace Continuous Zero Sections with "::"
If there are **one or more full hextets made entirely of zeros**, they can be replaced with a **double colon (::)**.  
This can be done **only once in an address**.


```bash
`Original`
2001:0DB8:0000:0000:0000:00FF:0042:8329

```

**After applying both rules:**
```bash
2001:DB8::FF:42:8329
```

This makes IPv6 addresses **shorter, cleaner, and easier to work with**.

If there are multiple zero sections of the same length, the **first one is usually compressed**.
