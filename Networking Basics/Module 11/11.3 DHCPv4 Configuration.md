# DHCP Address Assignment in a Small Network

There are two ways for a device to obtain an IPv4 address:
- Manually (Static Configuration)
- Automatically (DHCP – Dynamic Host Configuration Protocol)

In this network, all PCs obtain their IP addresses automatically from a DHCP-enabled router.

---

```bash
                       Internet
                          |
                          |
                  -----------------
                  |   DHCP Router  |
                  |  (172.16.0.1)  |  ← Default Gateway
                  -----------------
                     |      |      |
        --------------      |      --------------
        |                   |                   |
        |                   |                   |
   -----------         -----------         -----------
   |   PC0   |         |   PC1   |         |   PC2   |
   -----------         -----------         -----------
   DHCP: ON            DHCP: ON            DHCP: ON
   IP: 172.16.0.100    IP: 172.16.0.101    IP: 172.16.0.102
   GW: 172.16.0.1      GW: 172.16.0.1      GW: 172.16.0.1

```

## Router DHCP Configuration

The router has DHCP enabled by default.  
It already has an IP address assigned to its LAN interface, which becomes the default gateway for all PCs.

A range of IP addresses is reserved to be handed out dynamically to hosts.

>DHCP Pool Start Address:172.16.0.100

Each device that requests an IP address receives the next available address in the sequence.

Each PC automatically receives:

## Changing from Static to DHCP

Each PC initially has a statically configured IP address.  
When the configuration is changed to DHCP:
- The PC immediately sends a DHCP request
- The router responds with an available IP address
- The PC automatically applies the new settings

172.16.0.101  
172.16.0.102

## How DHCP Works

- IPv4 addresses can be assigned in two ways:
  - **Static** – Manually configured by a person.
  - **Dynamic** – Automatically assigned by a DHCP server.
- **DHCP** stands for **Dynamic Host Configuration Protocol**.
- It is the protocol used by a device to automatically obtain its IP addressing information.

---

## DHCP Communication Process

DHCP works using a series of message exchanges between the host and the DHCP server.

### 1. DHCP Discover
- The host sends a **DHCP Discover** packet.
- This packet is a **broadcast**.
- It contains:
  - The **MAC address** of the requesting device.
- It is sent to find any available **DHCP servers** on the network.

---

### 2. DHCP Offer
- Any DHCP server that receives the discover packet responds with a **DHCP Offer**.
- The offer contains:
  - An available **IPv4 address**
  - The **subnet mask**
  - The **default gateway**
- This is an address the host may use if it accepts the offer.

---

### 3. DHCP Request
- The host responds with a **DHCP Request** packet.
- This packet:
  - Formally **requests the offered IPv4 address**
  - Indicates the host’s intent to use the provided configuration

---

### 4. DHCP Acknowledgement (ACK)
- The DHCP server responds with a **DHCP Acknowledgement (ACK)**.
- This confirms:
  - The IP address is now officially assigned to the host
  - The assignment is recorded in the server’s table using the host’s **MAC address**
- The host applies the received configuration to its network settings.

---

## Devices That Can Act as DHCP Servers

- **Home networks:**
  - Wireless or wired routers commonly act as DHCP servers.
- **Large networks:**
  - Dedicated servers (Windows Server, Linux servers) often provide DHCP services.
- **General rule:**
  - Any device running DHCP service software can function as a DHCP server.
___

## DHCP DORA Process 

The DHCP process follows four main steps known as **DORA**:

---

### 1. Discover
**Client → Broadcast → Network**

- The client does not have an IP address.
- It sends a **DHCP Discover** message as a **broadcast**.
- Purpose: *Find any available DHCP servers.*
- Includes the client’s **MAC address**.

---

### 2. Offer
**DHCP Server → Client**

- A DHCP server responds with a **DHCP Offer**.
- The offer contains:
  - Proposed **IPv4 address**
  - **Subnet mask**
  - **Default gateway**
  - Other optional configuration details
- This is an **available address** the client may use.

---

### 3. Request
**Client → DHCP Server**

- The client sends a **DHCP Request** message.
- This message:
  - Accepts the offered IP address
  - Tells all DHCP servers which offer it selected

---

### 4. Acknowledgement (ACK)
**DHCP Server → Client**

- The DHCP server sends a **DHCP Acknowledgement (ACK)**.
- This confirms:
  - The IP address is **officially assigned**
  - The lease is recorded using the client’s **MAC address**
- The client applies the settings and can now communicate on the network.

---

## DORA Flow Summary



*Client → Discover → Network*  
*Server → Offer → Client*  
*Client → Request → Server*  
*Server → ACK → Client*

---

>[!tip] Key Notes
>
>- DHCP uses **broadcast and unicast** transmissions.
>- The IP address is **leased**, not permanently assigned.
>- The process happens automatically when a device joins a network.

## Configuring DHCP on a Home/Small Network Router

- **Two ways to assign an IP address to a device:**
  - **Static:** Manually configured.
  - **Dynamic:** Automatically assigned via DHCP.

- **Network Setup Example:**
  - Three PCs connected to a **DHCP-enabled router**.
  - Router has:
    - Switch ports
    - Wireless antenna
    - Internet connection
  - Most home routers provide a **GUI interface** to easily configure DHCP.

---

## Enabling DHCP on the Router

- DHCP is usually **enabled by default** on home routers.
- The router interface facing the LAN already has an assigned IP address.
- PCs connected to the router receive this IP as their **default gateway**.

### DHCP Address Pool Configuration

- A **range of IP addresses** is reserved on the network to hand out to hosts.
- Example configuration:
  - Start of DHCP range: **172.16.0.100**
  - Addresses are assigned sequentially as devices request them.

---

## Configuring PCs for DHCP

- Change the IP configuration on each PC from **static** to **DHCP**.
- Upon enabling DHCP:
  - Each PC broadcasts a **DHCP request**.
  - The DHCP server (router) assigns the next available IP address from the pool.

### Example Assignments:

| PC  | Assigned IP Address |
| --- | ------------------- |
| PC0 | 172.16.0.100        |
| PC1 | 172.16.0.101        |
| PC2 | 172.16.0.102        |

- Each device receives a **unique IP address**.
- PCs automatically get subnet mask, default gateway, and other configuration details.

---

## Testing Network Connectivity

- After IP addresses are assigned:
  - PCs can **ping each other** to verify connectivity.
  - Example:
    - PC0 pings PC1 (172.16.0.101) → Success
    - PC0 pings PC2 (172.16.0.102) → Success
- DHCP ensures that all devices on the network receive proper addressing and can communicate.
