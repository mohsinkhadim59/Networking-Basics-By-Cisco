## Client and Server Interaction

Everyday network activities (email, web browsing, social media, online shopping) rely on **clients** and **servers** communicating over a network using agreed-upon **standards and protocols**.

- **Client**: A device running software that requests services  
  - Examples: Web browsers (Chrome, Firefox), email clients (Outlook)
- **Server**: A host running software that provides services to clients  
  - Examples: Web servers, email servers, file servers

A single computer can run **multiple client applications at the same time** (e.g., browsing the web while checking email and streaming audio).

## Common Types of Server Software  

| Server Type      | Description                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Email Server** | Runs email server software. Clients use email applications (e.g., Microsoft Outlook) to send and receive messages. |
| **Web Server**   | Runs web server software. Clients use browsers (e.g., Chrome, Firefox) to access web pages.                        |
| **File Server**  | Stores corporate and user files centrally. Clients access files using tools like Windows File Explorer.            |

---

>[!Notes]
Modern internet applications depend on **many interacting clients and servers**.  
These interactions work reliably because they follow **standardized protocols**, allowing devices from different vendors and networks to communicate correctly.

## Web Client and Web Server Communication Steps

### 1. Web Request Overview
- A web client requests a web page from a web server located on a remote network.
- The web server listens for HTTP requests on **TCP port 80**.
- The client uses a **URL** (e.g., `www.learnip.com`) to identify the server.

---

### 2. DNS Resolution
- Networks do not use domain names; they use **IP addresses**.
- The client performs a **DNS lookup** to translate the URL into an IP address.
- Example:
  - `www.learnip.com` → `172.16.10.50`

---

### 3. TCP Connection Setup
- After DNS resolution, the client establishes a **TCP connection** to the server.
- The client uses:
  - Its own IP address (e.g., `192.168.10.15`)
  - A randomly chosen **ephemeral port** (>1024), e.g., `5507`
- The server uses:
  - Its IP address (`172.16.10.50`)
  - **TCP port 80**

---

### 4. Socket Identification
- A **socket** uniquely identifies the communication:
  - Source IP + Source Port
  - Destination IP + Destination Port
- Example socket:
  - `192.168.10.15:5507 → 172.16.10.50:80`

---

### 5. Server Processing
- The server receives the packet and places it in the buffer for **port 80**.
- The web service processes the request and prepares a response.

---

### 6. Server Response
- The server sends the reply with:
  - Source: `172.16.10.50:80`
  - Destination: `192.168.10.15:5507`
- All packets in this session use the same socket information.

---

### 7. Conversation Tracking
- Routers, firewalls, and other network devices use socket information to:
  - Identify packets belonging to the same conversation
  - Properly forward and manage traffic across the internet

## URI, URL, and URN

>[!Tip] **RESTful API**
>A **RESTful API** (Representational State Transfer Application Programming Interface) is ==an architectural style for building web services that uses standard HTTP methods to enable communication and data exchange between different software applications over the internet==.
### Uniform Resource Identifier (URI)
- A **URI** is a string of characters used to identify a resource on a network.
- It is a general identifier used for web resources and services (e.g., REST APIs).

---

### Types of URI
- **URN (Uniform Resource Name)**
  - Identifies a resource by name within a namespace
  - Does **not** specify how or where to access the resource
- **URL (Uniform Resource Locator)**
  - Identifies the **location** of a resource on a network
  - Includes the protocol used to access it
  - Examples: HTTP, HTTPS, FTP, SFTP, SSH  
  - Example: `sftp://sftp.example.com`

---

### Parts of a URI
![Parts of URI](/Imagesn/127.png)
- **Protocol / Scheme**  
  - Examples: `https`, `ftp`, `sftp`, `mailto`, `nntp`
- **Hostname**  
  - Example: `www.example.com`
- **Path and File Name**  
  - Example: `/author/book.html`
- **Fragment**  
  - Example: `#page155`
