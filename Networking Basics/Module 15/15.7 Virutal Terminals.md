## Telnet

### Overview
- **Telnet** is an application-layer protocol used for **remote text-based access** to computers
- Developed in the **early 1970s**, it is one of the oldest protocols in the TCP/IP suite
- Designed to allow users to interact with remote systems as if using a directly connected terminal

### How Telnet Works
- Telnet **emulates a text-based terminal** over a network
- Both the protocol and the client software are called **Telnet**
- Telnet servers listen for connections on **TCP port 23**

### Virtual Terminal Session
- A Telnet connection is called a **virtual terminal (vty) session**
- Uses software instead of physical terminals
- Provides access to the server’s **command-line interface (CLI)**
- The client can execute commands as if locally connected

### Security Consideration
- **Telnet is not secure**
  - Data (including usernames and passwords) is sent in **plain text**
- **SSH (Secure Shell)** is recommended instead of Telnet in modern networks

## Telnet vs SSH

### Telnet Capabilities
- After a Telnet connection is established, users can perform any **authorized action** on the server
- Actions include:
  - Starting and stopping processes
  - Configuring the device
  - Shutting down the system
- Functionally similar to working directly on the server’s command line

### Telnet Security Limitations
- Telnet may require user login, but it **does not encrypt data**
- All data is sent as **plaintext**
- Usernames, passwords, and commands can be **easily intercepted and read**
- Makes Telnet unsafe for modern networks

### Secure Shell (SSH)
- **SSH** is a secure alternative to Telnet
- Provides:
  - Secure remote login
  - Encrypted data transmission
  - Stronger authentication mechanisms
- Protects session data from interception

### Best Practice
- Always use **SSH instead of Telnet** whenever possible
- SSH prevents attackers from reading captured network traffic
![Security Measures](/Imagesn/142.png)
- Telnet traffic captured by an attacker is **readable**
- SSH traffic captured by an attacker is **encrypted and unreadable**
