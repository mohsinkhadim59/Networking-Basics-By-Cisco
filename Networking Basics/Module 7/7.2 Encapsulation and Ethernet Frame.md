# **Ethernet Frame **

Ethernet is a technology commonly used in **Local Area Networks (LANs)**.

- Devices connect using an **Ethernet Network Interface Card (NIC)**.
    
- Each Ethernet NIC has a **unique MAC address** permanently burned in.
    
- The **source and destination MAC addresses** are included in the Ethernet **frame header**.
    

Ethernet operates mainly at **Layer 2 (Data Link)** of the OSI model but also defines standards at **Layer 1 (Physical)**.
![Ethernet Frame](/Imagesn/62.png)
The sizes shown (in bytes) can be converted to bits by multiplying by **8**.

---

## **Fields of an Ethernet Frame**

### **1. Preamble**

- **Purpose:** Allows the receiving NIC to synchronize with the incoming bits.
    
- Acts like a “heads-up” before real data arrives.
    

---

### **2. Start Frame Delimiter (SFD)**

- Signals to the receiving NIC that **the actual Ethernet frame begins after this field**.
    

---

### **3. Destination MAC Address**

- The MAC address of the **recipient** NIC on the same local network.
    
- The frame is delivered to this specific hardware address.
    

---

### **4. Source MAC Address**

- The MAC address of the **sending** NIC.
    
- Identifies which device originally created the frame.
    

---

### **5. Length/Type Field**

This field has two possible meanings:

#### **Length:**

- Indicates the **number of bytes** in the data (payload) field.
    

#### **Type:**

- Indicates **what kind of payload** is carried, for example:
    
    - IPv4 packet
        
    - IPv6 packet
        
    - Other Layer 3 protocols
        

---

### **6. Data (Payload)**

- The actual encapsulated data being transported.
    
- Could include:
    
    - IPv4 or IPv6 packet
        
    - TCP/UDP header
        
    - Higher-level protocol data (HTTP, DNS, etc.)
        
- Ethernet **does not care** what the data is—its job is simply to deliver it.
    

---

### **7. Frame Check Sequence (FCS)**

- Used by the receiving device for **error detection**.
    
- Ensures that data was not corrupted during transmission.

## **Encapsulation **

In computer networks, data cannot be sent in its raw form. It must be organized into a specific structure so that devices can understand, deliver, and process it correctly.  
This structuring process is called **encapsulation**.

When a device sends data, each layer of the network model adds its own information  such as addresses, control information, or error-checking details. This added information “wraps” the original data, creating a final structured unit called a **frame** at the Data Link layer.

The frame includes important details such as:

- **Source address** – where the data came from
    
- **Destination address** – where the data must be delivered
    
- **Other control and error-checking fields**
    

If a frame is not structured correctly, the receiving device will ignore it because it cannot understand or trust the information inside.

On the receiving end, the opposite process happens. Each layer removes the information that was added during transmission. This is called **de-encapsulation**.

## **Improved Analogy**

Think of encapsulation like sending a package:
![Improved Analogy](/Imagesn/63.png)
1. You write a note (your original data).
2. You place it inside a box (encapsulation).
3. You put a shipping label with the sender and receiver address (frame header information).
4. The delivery service transports it.

If the address label is wrong or missing, the package never reaches the destination — just like a network frame that is incorrectly formatted.

When the receiver gets the package:

1. They remove the box.
2. Take out the note.
3. Read the original message.
This is **de-encapsulation** removing all packaging until the original content is revealed.
