# **How Ethernet Switches Work **

## **Switch Operating Layer**

- Ethernet switches operate at **Layer 2 (Data Link Layer)** of the OSI model.
- They make forwarding decisions based on the **Ethernet frame header**, specifically the **destination MAC address**.

---

## **MAC Address Table (Forwarding Table)**

- Switches maintain a **MAC address table** that maps:  
    **MAC Address → Switch Port**
- The table can be dynamically learned

---

## **Example: H1 Sends a Frame to H4**

**MAC Table**

| Host | MAC Address | Switch Port |
| ---- | ----------- | ----------- |
| H1   | AAAA        | Fa0/1       |
| H2   | BBBB        | Fa0/2       |
| H3   | CCCC        | Fa0/3       |
| H4   | DDDD        | Fa0/4       |
![Example](/Imagesn/65.png)
### **1. Frame Creation**

H1 prepares an Ethernet frame:

>- **Source MAC:** AAAA (H1)
>- **Destination MAC:** DDDD (H4)

### **2. Frame Sent to the Switch**

- H1 sends the frame into the switch via **FastEthernet0/1**.

### **3. Switch Forwarding Decision**

The switch checks:

> Destination MAC = **DDDD**

- It looks up **DDDD** in its MAC address table.
- The table indicates DDDD is on **Fa0/4**.
### **4. Selective Forwarding**

- The switch **forwards the frame ONLY out port Fa0/4**.
- All other ports are _not_ used.
This is known as **unicast forwarding**  the frame is delivered only to the correct port.

---

>[!tip]
>
> - Switches make decisions based on **Layer 2 MAC addresses**.
> - They use a **MAC address table** to determine the correct output port.
> - Only the port linked to the destination MAC receives the frame.
> - This reduces traffic and improves efficiency compared to hubs.

# **How a Switch Builds Its MAC Address Table**

Ethernet switches operate at **Layer 2 (Data Link Layer)** of the OSI model.  
They make forwarding decisions based on the **source and destination MAC addresses** found in the Ethernet frame header.

A switch uses a **MAC address table** (also called a CAM table) to know which MAC address is reachable through which port.  
This table is built **dynamically**, using a process called **MAC learning**.

---

# **1. Step 1  Switch Receives a Frame**

When a switch receives any Ethernet frame, the **first thing it does is examine the Source MAC address**.

Example: H1 → H4

- Source MAC: **AA-AA**
    
- Destination MAC: **DD-DD**
    
- Frame arrives on **FastEthernet0/1**
    

---

# **2. Step 2  Learning the Source MAC**

The switch checks:

> “Does AA-AA already exist in my MAC table?”

- If **NO**, it learns it:
    
    - Adds entry: **AA-AA → Fa0/1**
        
- If **YES**, it simply refreshes the entry timer (usually about 5 minutes).
    
![Learning MAC](/Imagesn/66.png)
This is how the switch **maps devices to ports**.

---

# **3. Step 3  Forwarding Decision**

Next, the switch checks the **destination MAC address**.

### Case A — Destination MAC Not in Table

If the switch does NOT know DDDD yet:

- This is an **Unknown Unicast**
    
- Switch **floods the frame out all ports** **except** the incoming port
    
- Other hosts receive the frame but **discard** it if the MAC does not match
    
- Only H4 accepts it
### Case B — Destination MAC Not in Table
  If the switch does know about the DDD it will simply forward the frame to the H4 just like in the above example.
  
---

# **4. Step 4  Reverse Direction Learning**

When H4 sends a reply back to H1:

- Source MAC = **DD-DD**
    
- Frame arrives on **Fa0/4**
    

Switch checks:

> “Is DD-DD already in my table?”

- If **NO**, it adds:
    
    - **DD-DD → Fa0/4**
        

Now both AA-AA and DD-DD are learned.
![Learning MAC](/Imagesn/66.png)

---

# **5. Step 5  Forwarding With a Full Table**

When H1 sends another frame to H4:

- Source MAC AA-AA already known → no update
    
- Destination MAC DD-DD **is now present** in table  
    → Switch forwards frame **only out Fa0/4** (no flooding)

---

>[!tip] Key Behaviors of Switch MAC Learning
>-  Switch Learns Source MAC
>	- Every frame teaches the switch something.
>-  Unknown Unicast Frames Are Flooded
>	- Flooding happens only when the destination MAC is unknown.
>-  Known Unicast Frames Are Filtered
>	- Forwarded only out the specific correct port.
>-  Entries Age Out
>	- Usually around **5 minutes** if no frames are received.


>[!notes]
>The temporary connection that switch builds between two end devices is known as Circuit.
