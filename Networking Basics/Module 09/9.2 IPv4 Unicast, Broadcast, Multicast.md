## Unicast IP Transmission 

### What Is Unicast?
- **Unicast** is a type of IP transmission where data is sent **from one device to one specific device**.
- It is the most common type of communication on IP networks.
-  Range : `1.1.1.1 to 223.255.255.255`
- However, within this range are many addresses that are reserved for special purposes

>[!tip]
> A unicast packet has a destination IP address that is a unicast address which goes to a single recipient. A source IP address can only be a unicast address, because the packet can only originate from a single source. This is regardless of whether the destination IP address is a unicast, broadcast, or multicast.

>[!example] 
>- Source device: **172.16.4.1**
>- Destination device (printer): **172.16.4.253**
>![Unicast](/Imagesn/73.png)
><p align="center"><em>Figure 1: Unicast Destination and Source Address</em></p>
>- The packet:
  >- **Source IP:** 172.16.4.1
>  - **Destination IP:** 172.16.4.253
>  ![Unicast](/Imagesn/74.png)
><p align="center"><em>Figure 2: Unicast Transmission</em></p>
>- The message goes from **one device → one device**, which is unicast.

>[!note]
>- A **source IP address is always unicast**, because a packet can only originate from one device.
>- A **destination IP address can also be unicast**, meaning the packet is intended for a single device only.
>- Moreover, IPv4 unicast host addresses are in the address range of 1.1.1.1 to 223.255.255.255. However, within this range are many addresses that are reserved for special purposes

## Broadcast Transmission

- A **broadcast transmission** occurs when a device sends a packet to **all devices on the same network**.
>[!Example]
>- The packet has:
>- **Source IPv4 address:** 172.16.4.1
>- **Destination IPv4 address:** 255.255.255.255
  >![Limited Broadcast](/Imagesn/76.png)
  ><p align="center"><em>Figure 3: Limited Broadcast</em></p>
>- The destination address 255.255.255.255 is a **special broadcast address**, meaning the packet is intended for every device on the local network.
>
>

###  Broadcast Working
- The switch sends (floods) the broadcast packet out **all ports except the one it was received on**.
- Every device on the network receives the packet.
- When the router receives a broadcast, it **does not forward** it to other networks.

>[!note]
>- IPv4 supports broadcast packets.
>- IPv6 does **not** use broadcast; it uses multicast instead.
>- A broadcast must be processed by all devices in the **same broadcast domain**, which is a group of hosts on the same network segment.
>- Broadcasts can be:
  >- **Directed broadcast** – sent to all hosts on a specific network.
  >- **Limited broadcast** – sent to all hosts on the local network only.

>[!Example] Example of  a directed broadcast address:
>- For the network **172.16.4.0/24**, the directed broadcast address is **172.16.4.255**.
# Types of IPv4 Broadcasts

## **Directed Broadcast**

Sent to **all hosts of a specific network**.

>[!Example]  
Network: `172.16.4.0/24`  
Directed broadcast: `172.16.4.255`

This packet is meant for _that subnet only_.

---

##  **Limited Broadcast**

Sent to **255.255.255.255**  
Used when the sender **does not know the network information**, or during booting (like DHCP Discover).

This packet stays **only in the local network**.
>[!tip]
>Broadcast packets use resources on the network and make every receiving host on the network process the packet. Therefore, broadcast traffic should be limited so that it does not adversely affect the performance of the network or devices. Because routers separate broadcast domains, subdividing networks can improve network performance by eliminating excessive broadcast traffic

## Multicast Transmission

- **Definition:**  
  **Multicast transmission** reduces traffic by allowing a host to send a single packet to a selected set of hosts that subscribe to a multicast group.

- **IPv4 Multicast Addresses:**  
  - Range: **224.0.0.0 to 239.255.255.255**

- **How It Works:**  
  - A source device sends a packet to a **multicast group address**.  
  - Multiple devices on the network may receive the packet, but only devices that are **members of the multicast group** will process it.

>[!Example]  
>- Source IP: **172.16.4.1**  
>- Multicast recipients: **172.16.4.3 and 172.16.4.4**  
  >- Packet is sent from 172.16.4.1 to the network.
  >- All devices may receive the frame at Layer 2.
  >- Only **172.16.4.3 and 172.16.4.4** actually process the packet because they are members of the multicast group.

## Multicast Packets and Multicast Clients

- **Definition of a Multicast Packet:**  
  - A multicast packet is a packet with a **destination IP address that falls within the multicast range**.  
  - IPv4 multicast range: **224.0.0.0 to 239.255.255.255**

- **Multicast Clients:**  
  - Hosts that receive specific multicast packets are called **multicast clients**.  
  - Multicast clients use services requested by a client program to **subscribe to a multicast group**.

- **Multicast Groups:**  
  - Each multicast group is represented by a **single IPv4 multicast address**.  
  - When a host subscribes to a multicast group:
    - It processes packets addressed to the **multicast address**.  
    - It also continues to process packets addressed to its **unicast address**.

- **Use in Routing Protocols:**  
  - Some routing protocols, such as **OSPF**, use multicast transmissions.  
  
   >[!Example]
   >- Routers enabled with OSPF communicate using the multicast address **224.0.0.5**.
   >- Only devices running OSPF process packets sent to 224.0.0.5.
    >- All other devices **ignore** these multicast packets.
