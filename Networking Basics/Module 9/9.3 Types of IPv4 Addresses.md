## Public and Private IPv4 Addresses 

IPv4 addresses come in different types depending on their use.  
Some are meant for communication on the public internet, while others are reserved only for internal networks.

### **Public IPv4 Addresses**
- Globally unique and routable on the internet.
- Assigned by ISPs or regional internet registries.
- Used for devices/servers that must be reachable from anywhere.

### **Private IPv4 Addresses**
- Introduced in the mid-1990s due to IPv4 exhaustion.
- Not routable on the public internet.
- Free to use inside any internal network (LANs, companies, homes).
- Defined in **RFC 1918**.

### **RFC 1918 Private Ranges**
| Network | Private Address Range |
|--------|------------------------|
| **10.0.0.0/8** | 10.0.0.0 – 10.255.255.255 |
| **172.16.0.0/12** | 172.16.0.0 – 172.31.255.255 |
| **192.168.0.0/16** | 192.168.0.0 – 192.168.255.255 |

### **Key Points**
- Private addresses are **not unique** globally.
- They allow organizations to have many internal hosts without using public IPs.
- The long-term solution to IPv4 shortage is **IPv6**.

# Public vs Private IPv4 Addresses

When we use IPv4 addresses, they are not all the same.  
Some can go **onto the internet**, and some can **only be used inside local networks** like homes, schools, or companies.


---

#  1. Public IPv4 Addresses

A **public IP address** is:

- **Globally unique** → no two devices on the entire internet share it
    
- **Assigned by ISPs**
    
- **Routable on the internet** → meaning the internet routers know how to reach it
    

>[!Example]- A Website Server 
A website server (like google.com) must use a public IP so anyone in the world can connect.
Think of a **public IP like your home’s street address**.  
Anyone can send you mail.

---

#  2. Private IPv4 Addresses

In the mid-1990s, the internet started running out of IPv4 addresses.  
So they created **private addresses** that:

- Are **NOT** routable on the public internet
    
- **Can be reused** in every home, school, company
    
- Are **free to use** where no ISP needed
    
- Are used only **inside local networks**
    

These private ranges are defined by **RFC 1918**.

### The 3 private ranges:

| Range              | Meaning                                     |
| ------------------ | ------------------------------------------- |
| **10.0.0.0/8**     | Huge networks (big companies, data centers) |
| **172.16.0.0/12**  | Medium-size networks                        |
| **192.168.0.0/16** | Most common in home routers (192.168.0.x)   |

>[!Example]- Simple Example  
> - Your home Wi-Fi probably uses **192.168.1.1** as the router address.
> - Private IPs are like **your room number inside a building**.  
> - People on the street can’t see your room number — only inside the building.


---

#  Why can’t private IPs go on the internet?

Routers on the internet are programmed to **drop RFC 1918 addresses**.  
Because these are **internal only**.

So if a computer with address 192.168.1.5 directly tries to go online, the internet routers would reject it.

This is why we need **NAT (Network Address Translation)**

---

#  3. Why private addresses were created

Because IPv4 has only **4.29 billion** total addresses, and the world ran out.

Using private IPs:
- Every home can reuse 192.168.x.x
- Every company can reuse 10.x.x.x
- Everyone can reuse the same private ranges without conflict
This allowed the internet to keep working until IPv6 came along.

---
## **Routing to the Internet 

Most organizations and home networks use **private IPv4 addresses** for all internal devices.  
However, these private addresses **cannot be routed on the public internet**.

### **Why Private IPs Cannot Go to the Internet**

- Private IPv4 addresses are **not globally routable**.
    
- When internal devices send traffic to the internet, the packets have:
    
    - **Source:** Private IP (not allowed on the internet)
        
    - **Destination:** Public IP (internet server)
        
- ISPs must **discard** or **translate** any packet that contains a **private source IP**.
### **Network Address Translation (NAT)**

Before packets can leave the internal network, the router must perform **NAT**.

NAT does the following:

- **Replaces the private source IP** with a **public IPv4 address**.
- Allows multiple internal devices to share **one public IP**.    
- Occurs on the **router connecting to the ISP**.
![NAT](/Imagesn/79.png)


>[!tip]
>
>- Private IPs = used inside intranets; cannot go directly to the internet.
>- NAT = required to convert private → public IPv4 for internet routing.  
>- Without NAT, packets with private addresses would be **dropped** by the ISP.

## **Special Use IPv4 Addresses 

Some IPv4 addresses have special purposes.  
Certain addresses cannot be assigned to hosts (like network or broadcast addresses), while others **can** be assigned but have **restricted use**.

### **Loopback Addresses**

- Range: **127.0.0.0/8**  
    `(127.0.0.1 → 127.255.255.254)`
- Most commonly used: **127.0.0.1**
- **Purpose**: A host uses this address to **send traffic to itself**.

- Common use:
>	 `ping 127.0.0.1` → tests the TCP/IP stack of the local device.
![PING](/Imagesn/80.png)
### **Link-Local Addresses**

- Range: **169.254.0.0/16**  
    `(169.254.0.1 → 169.254.255.254)`
    
- Also called: **APIPA** (Automatic Private IP Addressing) or **self-assigned** addresses.
    
- **Purpose**: Assigned automatically when a device **cannot get an IP address** from DHCP or other configuration methods.
    
- Usage:
    
    - Works only **within the same local link**.
        
    - Can be used for peer-to-peer connections.
        
    - Not commonly used in normal networks.

# Legacy Classful Addressing (RFC 790)

> Classful addressing was the original scheme for allocating IPv4 network addresses, defined in [RFC 790](https://tools.ietf.org/html/rfc790).  
> It used fixed network prefixes (A, B, C) and ignored subnetting until the 1990s when CIDR (Class‑Less Inter‑Domain Routing) replaced it.

---

## 1. Class Definitions (Unicast)

|Class|Network Prefix|Host Address Count|Typical Use Case|Example|
|---|---|---|---|---|
|A|`/8`|16 777 214|Extremely large networks|`10.0.0.0/8`|
|B|`/16`|65 534|Medium‑size to large networks|`172.16.0.0/16`|
|C|`/24`|254|Small networks|`192.168.1.0/24`|

> [!Notes]
> - The first octet in A/B/C indicates the network; the remaining octets are hosts.
> - Class A and B provided vast address space per network; Class C was much smaller.

---

## 2. Other Class Ranges

| Class | Address Range                   | Purpose                 | Example       |
| ----- | ------------------------------- | ----------------------- | ------------- |
| D     | `224.0.0.0` – `239.255.255.255` | Multicast               | `224.0.0.0/4` |
| E     | `240.0.0.0` – `255.255.255.255` | Experimental / Reserved | `240.0.0.0/4` |

---

## 3. Why Classful Was Problematic

| Issue                | Impact                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| Wasted Address Space | Class A networks (50 % of allocations) often had millions of unused host slots.                        |
| Limited Flexibility  | Fixed prefixes forced oversized or undersized networks.                                                |
| Rapid Growth         | With the Web in the mid‑1990s, the Internet grew fast, revealing the inefficiencies of static classes. |

---

## 4. Transition to Classless Addressing

- Classless ignores the A/B/C boundaries.
- Uses Variable‑Length Subnet Mask (VLSM) / CIDR notation (`/prefix‑length`).
- Allocation based on actual host requirements, leading to more efficient use of the 4 billion IPv4 addresses.
