## Computer Network Protocols

- **Protocols** are rules that govern communication much like human communication rules such as using a common language, speaking formally or informally, or knowing how to greet someone.
- In computer networks, protocols ensure devices understand each other and can exchange information smoothly.

___

### Key Protocols in a Network Message

- **Ethernet**
  - Governs communication between devices on the same local network (like computers in a home or office).
  - **Real-life example:**  
    When you print something on a printer connected to the same Wi-Fi network, your computer and the printer communicate using Ethernet protocols.

- **IP (Internet Protocol)**
  - Controls how data travels from the original source to the final destination across multiple networks.
  - **Real-life example:**  
    When you send an email to someone in another country, IP helps route your message through many routers across the world until it reaches the recipient’s server.

- **TCP (Transmission Control Protocol)**
  - Ensures reliable delivery of data, reorders packets if they arrive out of order, and resends any that were lost.
  - **Real-life example:**  
    When downloading a large file, TCP ensures every piece of the file arrives correctly. If one piece doesn’t arrive, TCP asks the sender to send it again.

- **HTTP (Hypertext Transfer Protocol)**
  - Governs the transfer of webpages and web content (HTML, images, scripts).
  - **Real-life example:**  
    When you type *www.google.com* in your browser, HTTP is the protocol used to request the webpage and deliver it back to you.

___

### Why Protocols Matter
- Understanding these protocols helps you:
  - See how network communication works,
  - Configure and manage networks more effectively,
  - Troubleshoot problems faster when something goes wrong.

___

##  Protocol Stacks in Network Communication

- Successful communication on a network requires **multiple protocols working together**, not just one.
- These protocols are organized into layers, often described using the **TCP/IP Model**, which includes:
  - **Network Access Layer**
  - **Internet Layer**
  - **Transport Layer**
  - **Application Layer**
- When a device sends a message, it uses protocols from each layer — this collection is called a **Protocol Stack**.

---

# Using a Protocol Stack

#### **1. Network Access Layer – Ethernet**
- Handles communication from one network interface card (NIC) to another on the **same local network**.
- **Real-life example:**  
  When your laptop sends data to your Wi-Fi router, Ethernet rules determine *how* that data is physically delivered.

#### **2. Internet Layer – IP (IPv4 or IPv6)**
- Ensures the message travels from the original source to the correct destination, even across many networks.
- **Real-life example:**  
  When you send a WhatsApp message to someone in another country, IP is what helps your data hop through routers worldwide until it reaches their phone.

#### **3. Transport Layer – TCP**
- Provides **reliable delivery**, making sure the message arrives complete and in the correct order.
- **Real-life example:**  
  When downloading a software update, TCP checks that every piece of data arrives. If something is missing, it asks for it again so the file isn’t corrupted.

#### **4. Application Layer – HTTP**
- Governs how specific types of data are exchanged; in this case, **HTML for webpages**.
- **Real-life example:**  
  When you open YouTube in your browser, the page you see is delivered using HTTP.

---

>[!Important] 
>- Sending a single message such as loading a webpage actually uses **multiple protocols stacked together**.
>- Understanding protocol stacks helps explain **how networks really work**, and is key for network configuration and troubleshooting.

### **Revision of TCP/IP Model**

### **Overview**

Layered models help visualize how different protocols work together to enable network communication.  
Each layer has specific responsibilities and interacts with the layers above and below.

![TCP/IP Model](/Imagesn/52.jpg)
### **Benefits of Layered Models**

- Help in protocol design by clearly defining functions at each layer.
    
- Encourage vendor competition by ensuring interoperability.
    
- Allow technological changes in one layer without affecting others.
    
- Provide a common language to describe networking functions and capabilities.
    

### **About the TCP/IP Model**

- Developed in the early 1970s as the first internetwork communication model.
    
- Defines **four layers**, each responsible for essential network communication functions.
    
- The suite of TCP/IP protocols used on the internet follows this model, which is why it is commonly called the **TCP/IP Model**.
    

---

## **TCP/IP Model Layers**

| **Layer**          | **Description**                                                         |
| ------------------ | ----------------------------------------------------------------------- |
| **Application**    | Represents data to the user; includes data encoding and dialog control. |
| **Transport**      | Supports communication between devices across various networks.         |
| **Internet**       | Determines the best path through the network.                           |
| **Network Access** | Controls hardware devices and media used in the network.                |

# Reference Model vs Protocol Model

## **OSI Reference Model – Summary**

### **Overview**

There are two types of models used to describe network communication functions:

### **1. Protocol Model**

- Matches the structure of a specific protocol suite.
    
- Defines the functions that occur at each layer of the protocol suite.
    
- Example: **TCP/IP model** (because it shows how TCP/IP protocols operate layer-by-layer).
    

### **2. Reference Model**

- Describes what functions must happen at each layer but does **not** specify the exact way to implement them.
    
- Helps in understanding network operations clearly.
    
- Example: **OSI Model**, widely used for learning, network design, and troubleshooting.

![OSI](Imagesn/53.jpg)
The OSI model is a **reference model** used to describe how data moves through a network.  
It has **7 layers**, each with specific functions.

---

## **OSI Model Layers **

| **Layer**            | **Description**                                                             | **Examples**                                                    |
| -------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------- |
| **7 – Application**  | Provides network services directly to end-user applications.                | HTTP, HTTPS, FTP, SMTP, DNS, SSH, Telnet                        |
| **6 – Presentation** | Translates data formats, handles encryption and compression.                | SSL/TLS, JPEG, MP3, PNG, ASCII, UTF-8                           |
| **5 – Session**      | Manages sessions between applications (start/maintain/end).                 | NetBIOS, RPC, SQL sessions, API sessions                        |
| **4 – Transport**    | Ensures end-to-end delivery with segmentation, flow control, reliability.   | TCP, UDP, SCTP, port numbers (e.g., 80, 443)                    |
| **3 – Network**      | Handles logical addressing and routing of packets between networks.         | IP, IPv4/IPv6, ICMP, ARP*, OSPF, RIP, BGP                       |
| **2 – Data Link**    | Transfers frames between devices over the same network; uses MAC addresses. | Ethernet, Wi-Fi (802.11), MAC addresses, Switches, VLANs        |
| **1 – Physical**     | Defines electrical/physical transmission: cables, signals, connectors.      | Fiber, Copper (Ethernet cables), Hubs, Repeaters, Radio signals |

>[!note]
> * ARP sits between Layer 2 and Layer 3 but is often taught with Layer 3 examples.

# **OSI Model vs TCP/IP Model **

## **Learning the usage of both in Networking**

Even though **TCP/IP is the protocol suite used on the internet**, the **OSI model** is still essential because:

- The **TCP/IP model only describes how TCP/IP protocols interact**, not how all networks generally operate.
    
- **TCP/IP** does **not** define lower-layer functions such as:
    
    - how to access physical media
        
    - how signals are encoded
        
- OSI **Layers 1 and 2** provide these detailed descriptions.
    
- The OSI model gives a **universal language** for networking concepts that apply beyond TCP/IP.
    

The OSI model is a **reference model**, while TCP/IP is a **protocol model**.

---

# **How TCP/IP Maps to the OSI Model**

| **OSI Model**             | **TCP/IP Model** | **Relation**                                                           |
| ------------------------- | ---------------- | ---------------------------------------------------------------------- |
| **Layer 7: Application**  | Application      | TCP/IP Application layer combines OSI Layers **5, 6, 7**.              |
| **Layer 6: Presentation** | Application      | (Handled within TCP/IP applications)                                   |
| **Layer 5: Session**      | Application      | (Handled within TCP/IP applications)                                   |
| **Layer 4: Transport**    | Transport        | **Direct match** — both ensure reliable/unreliable delivery (TCP/UDP). |
| **Layer 3: Network**      | Internet         | **Direct match** — routing, addressing (IP).                           |
| **Layer 2: Data Link**    | Network Access   | TCP/IP Network Access includes OSI Layers **2 + 1** together.          |
| **Layer 1: Physical**     | Network Access   | (Same as above)                                                        |

>[!tip] One can remember all the above layer by using this phrase where each word's first alphabet corresponds with the layer name: 
>**ALL PEOPLE SEEM TO NEED DATA PROCESSING**

# **Key Relationships Between the Models**

 **1. OSI Layer 3 = TCP/IP Internet Layer**

- Handles **routing**, **logical addressing**, **packet forwarding**.
    
- Examples: IP, ICMP, routing protocols.
    

 **2. OSI Layer 4 = TCP/IP Transport Layer**

- Responsible for **reliability**, **segmentation**, **flow control**, **ports**.
    
- Examples: TCP, UDP.
    
**3. TCP/IP Application Layer = OSI Layers 5 + 6 + 7**

The OSI model splits the upper-layer functions into:

- **Layer 7 – Application**
    
- **Layer 6 – Presentation** (encoding, encryption, compression)
    
- **Layer 5 – Session** (session control)
    

TCP/IP groups all of these into one **Application layer**.

---

# Why We Still Use OSI Today

- OSI clearly separates **Data Link (Layer 2)** and **Physical (Layer 1)**.  
    This makes it ideal for discussing things like:
    
    - Ethernet
        
    - MAC addresses
        
    - Cables
        
    - Radio frequencies
        
    - Fiber optics
        
- OSI is more detailed, making it excellent for:
    
    - teaching
        
    - documentation
        
    - troubleshooting
        
    - application design
        
- TCP/IP is best for explaining **how the internet works** and how real-world protocols operate.
