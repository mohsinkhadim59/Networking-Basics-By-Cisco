# Private IP Networks and Network Address Translation (NAT)


---

## IPv4 Address Categories

There are **two main categories of IPv4 addresses**:

### 1. Private IP Addresses
Private addresses are used **inside organizations and homes**.  
They **can communicate internally**, but **cannot be routed on the public internet**.

The reserved private IPv4 ranges are:

- **10.0.0.0 – 10.255.255.255**  
- **172.16.0.0 – 172.31.255.255**  
- **192.168.0.0 – 192.168.255.255**

These addresses:
- Work normally inside a local network
- Can be routed between internal networks
- Are **blocked by the internet backbone**

---

### 2. Public IP Addresses
Public addresses:
- Are **globally unique**
- Are **assigned by ISPs**
- Are **required for internet communication**
- **Can be routed anywhere on the internet**

---

## Why NAT is Required

If a device with a private IP address tries to send data to the internet:
- The **internet will reject it**
- Because **private IPs are not globally routable**

To solve this problem, **Network Address Translation (NAT)** is used.

---

## What NAT Does

**NAT allows privately addressed devices to access the public internet** by:

- Replacing the **private source IP**
- With a **public registered IP**
- Keeping track of the connection in a **translation table**

The **router** performs this function.

---

## Simple NAT *Example* 

### Internal Network (Private)

```bash
PC-1  →  192.168.1.15
PC-2  →  192.168.1.16
GW    →  192.168.1.1
````

### Router Public Address

```bash
Router Public IP → 200.100.58.51
```

### Internet Server

```bash
Web Server → 210.100.5.5
```

---

## NAT Packet Flow - Stepwise

### Step 1 – Packet leaves the PC (Private Network)

```bash
Source IP:      192.168.1.15
Destination IP: 210.100.5.5
```

---

### Step 2 – Router Translates the Packet (NAT Applied)

The router checks its NAT table and converts:

```bash
Source IP becomes: 200.100.58.51
Destination IP:   210.100.5.5
```

Now the packet is **valid for the internet**.

---

### Step 3 – Server Replies

The server responds to:

```bash
Source IP:      210.100.5.5
Destination IP: 200.100.58.51
```

---

### Step 4 – Router Reverses NAT

The router looks up **200.100.58.51** in its NAT table and changes:

```bash
Destination IP → 192.168.1.15
```

The packet is safely delivered back to **PC-1**.

---

## What the NAT Table Does

The NAT table keeps track of:

- Internal private IP
    
- External public IP
    
- Active connections
    

Example mapping:

```bash
192.168.1.15  ↔  200.100.58.51
192.168.1.16  ↔  200.100.58.52
```

This allows **multiple private devices to share one public address**.

---

> [!note] Key Concepts
> 
> - Private IPv4 addresses **cannot travel on the public internet**
>     
> - Public IPv4 addresses **are required for internet access**
>     
> - NAT allows private devices to **communicate using a public address**
>     
> - The router **modifies source and destination IPs**
>     
> - The NAT table ensures responses return to the **correct private host**
>
